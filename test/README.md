# PDF 遮罩一致性測試

搭配 `fix/pdf-redaction-consistency` 分支使用。目的是驗證
**「預覽看到的遮罩」與「下載檔裡的遮罩」完全一致**。

## 測試檔：`quote-shield-testcase.pdf`

四頁，每頁針對一個已知缺陷：

| 頁 | 內容 | 驗證目標 | 舊版行為 |
|---|---|---|---|
| P1 | 直立，3 個命中項 | 基準線 | 正常 |
| P2 | **旋轉 90°**，3 個命中項 | 旋轉頁座標 | ❌ 零面積框＝等於沒遮 |
| P3 | **旋轉 270°**，3 個命中項 | 旋轉頁座標 | ❌ 同上 |
| P4 | **純圖片、無文字層**，3 個命中項 | OCR 是否寫進下載 | ❌ 預覽有遮、**下載檔全裸** |

每頁另有一行 `gypsy quaggy jumpy`，用來看遮罩是否蓋到基線下伸部（g/y/p）。

命中項為 email / 電話 / 身分證號格式各一。

## 步驟

1. 開啟本分支的 `quote-shield.html`
2. 上傳 `quote-shield-testcase.pdf`
3. **務必勾選「啟用 OCR 圖片辨識」**（否則測不到 P4，那正是最嚴重的缺陷）
4. 檢查預覽：四頁應各有 3 條黑槓
5. 下載 PDF
6. **逐頁比對下載檔與預覽**——數量與位置都要一致

## 判定

- ✅ 通過：四頁的黑槓數量、位置都與預覽相同；P4 的三行資料在下載檔中不可見
- ❌ 失敗：任何一頁數量對不上，或 P4 的 email / 電話 / 身分證號在下載檔中看得到

## 對照組

用 `main` 分支跑同一份檔案，P2 / P3 / P4 應該會出問題——
可直接看出修補前後的差異。

## 第二階段修補（兩階段處理 + 確認關卡 + AI 關鍵字標示）

### 額外要驗的三件事

**A. 每頁遮罩數量一致**
預覽每頁標題列現在會顯示「遮罩 N」。下載後逐頁點算黑框數量，
應與該頁標示的 N 相同。

**B. 結果可重現（原本是隨機的）**
同一份檔案、同樣設定，**連續處理兩次**，每頁的「遮罩 N」數字應完全相同。
舊版因為 NER 會在逐頁掃描過程中持續加入關鍵字，
第 1 頁與最後一頁套用的規則不同，重跑結果也會變動。

**C. 確認關卡**
- 預覽完成後，下載鈕應為**停用**狀態
- 勾選「我已逐頁確認遮罩正確」後才會啟用
- 勾選後再**手繪一個框**或**刪掉一個關鍵字** → 勾選應自動取消、下載鈕再次停用

### AI 關鍵字

開啟 NER 後，自動偵測到的關鍵字會標上橘色 `AI` 標籤。
確認不需要的可直接點 `×` 移除，不必整個關閉 NER。

## 第三階段（效能／記憶體）

正確性不變，只改資源使用方式。**應驗證輸出與前一版一致**：

- 同一份檔案在修改前後產出的 PDF，遮罩位置與數量應相同
- 掃描頁（P4）的輸出檔會明顯變小（改用 JPEG），畫質應仍可接受
- 有文字層的頁面仍為 PNG，文字邊緣不應出現壓縮雜訊

**新增可觀察的行為**
- 下載時會顯示「處理中 i/總頁數」進度
- 大檔處理過程中瀏覽器不應再跳「網頁沒有回應」
- 復原（undo）現在會重新繪製該頁，速度略慢但記憶體不再累積
